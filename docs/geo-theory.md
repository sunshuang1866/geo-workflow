## 1. 什么是 GEO

**GEO（Generative Engine Optimization，生成式引擎优化）** 是指通过调整内容的结构、语义和可引用性，提升该内容被生成式 AI 平台（如 ChatGPT、Gemini、DeepSeek 等）准确引用的可能性的系统性方法论。

### 1.1 背景

2022 年以来，大语言模型（LLM）驱动的 AI 搜索工具快速普及。与传统搜索引擎"显示链接列表"不同，AI 搜索平台直接生成综合性回答，同时引用参考来源。这一模式改变了用户获取信息的方式：

- **传统搜索**：用户看到蓝色链接列表 → 自行筛选 → 点击跳转阅读原文
- **AI 搜索**：AI 综合多个来源 → 生成结构化回答 → 内嵌引用链接（用户可能不会点击）

在这一新范式下，**"是否出现在搜索结果页"** 变得不再重要，重要的是 **"内容是否被 AI 准确理解并引用"**。

### 1.2 GEO 的核心目标

| 目标 | 说明 |
|------|------|
| **引用率（Citation Rate）** | 在 AI 平台回答某类问题时，官方来源被引用的比例 |
| **引用准确性** | 被引用的内容与官方实际表述一致（无幻觉、无过时内容） |
| **引用位置** | 官方来源作为主要推荐（primary）而非次要参考（secondary） |

## 2. GEO 与 SEO 的区别

### 2.1 核心差异对比

| 维度 | 传统 SEO | GEO |
|------|---------|-----|
| **目标受众** | 搜索引擎爬虫（算法） | 生成式 AI 语言模型 |
| **优化对象** | 页面排名（SERP 位置） | 内容被引用的可能性和质量 |
| **关键信号** | 外链数量、关键词密度、页面权重（PageRank） | 内容直接回答能力、结构清晰度、事实精确性、可引用性 |
| **效果指标** | 点击率（CTR）、页面流量 | 引用率、引用准确率、引用位置 |
| **生效周期** | 数周至数月 | 取决于 AI 平台的内容索引周期（通常为周级） |
| **内容形式** | 长尾关键词覆盖、元标签优化 | 直接回答式写法、结构化数据标记、FAQ 覆盖 |

### 2.2 SEO 优化不等于 GEO 优化

SEO 优化有助于 AI 爬虫找到内容，但不能保证内容被正确理解和引用。GEO 需要额外关注：

1. **内容直接性**：AI 优先提取"首段直接给出答案"的内容，而非"铺垫 500 字再给结论"的内容
2. **结构化语义**：Schema.org 标记（FAQPage、HowTo、TechArticle）帮助 AI 理解页面类型
3. **事实精确性**：含有精确数字、版本号、具体步骤的内容比模糊描述更容易被引用
4. **实体消歧**：专有名词（如 "TransData"）需要在页面内明确说明是哪个产品的概念

### 2.3 GEO 与 SEO 的关系

```
SEO（让 AI 爬虫能找到内容）
    └── 必要条件：robots.txt 不阻止 AI 爬虫、Sitemap 完整、页面可渲染

GEO（让 AI 能理解并正确引用内容）
    └── 充分条件：内容直接回答、结构清晰、语义精确、消除歧义

SEO 是 GEO 的前提，但 GEO 需要额外的内容层优化。
```

## 3. AI 平台的内容引用机制

理解 AI 如何决定引用哪些内容，是制定 GEO 优化策略的基础。

### 3.1 主流平台的检索-生成架构

大多数 AI 搜索平台（如 ChatGPT Search、Perplexity、Gemini 的联网模式）采用 **RAG（Retrieval-Augmented Generation，检索增强生成）** 架构：

```
用户提问
    │
    ▼
[检索阶段] 调用搜索引擎 API（必应、谷歌等）获取 Top-N 页面
    │
    ▼
[解析阶段] 抓取页面内容，提取文本（无法解析纯图片/JS 渲染内容）
    │
    ▼
[理解阶段] LLM 分析页面内容是否与问题相关，提取关键信息片段
    │
    ▼
[生成阶段] LLM 综合多个来源生成回答，标注引用来源
    │
    ▼
回答 + 引用链接
```

### 3.2 影响引用概率的关键因素

**检索阶段**（搜索引擎能否找到页面）：
- 域名权威性（Domain Authority）
- robots.txt 是否允许 AI 爬虫（GPTBot、ClaudeBot、PerplexityBot 等）
- Sitemap 覆盖完整性
- 页面加载速度和 SSR 可渲染性

**解析阶段**（AI 能否提取到有效内容）：
- 页面在无 JS 环境下是否有实质内容（避免纯 SPA 客户端渲染）
- 语义化 HTML 标签（`<article>`、`<main>`、`<section>`）
- 图片内容是否有文字描述（alt 文本、图注）

**理解阶段**（AI 能否正确理解内容含义）：
- 首段是否直接回答问题
- 专有术语是否有上下文定义
- 内容是否有歧义性（同名不同义的概念会导致误引用）

**生成阶段**（AI 是否选择引用这个来源）：
- 内容是否比其他来源更直接、更精确
- 是否有可被引用的"独占性内容"（原创数据、官方实验结果）
- 内容时效性（更新日期越近，越被优先引用）

### 3.3 独立于 LLM 知识库的问题

部分 AI 平台（如 ChatGPT 的非联网模式）依赖训练时的知识库，而非实时检索。这意味着：
- 知识截止日期后的新内容无法被引用
- 即使官方文档内容正确，训练数据中如果第三方错误内容更多，AI 可能倾向于给出错误答案

**GEO 的局限性**：本系统评估的是"AI 平台联网搜索时对官方内容的引用情况"，对纯知识库问题的影响有限。

## 4. 本系统的评分模型

### 4.1 评分哲学

本系统采用 **"官方 URL 引用率"** 作为核心评分指标，而不是评估 AI 回答的语义质量。

**选择此方案的理由**：
- **客观可复现**：URL 匹配是确定性计算，相同输入始终得到相同结果
- **无幻觉风险**：用 LLM 评估 LLM 的回答质量，本身存在主观性和不稳定性
- **可解释**："平台 X 在回答问题 Y 时引用了 URL Z" 比 "AI 认为回答充分" 更容易被团队接受
- **可操作**：URL 不被引用 → 具体的内容和 SEO 改进措施清晰对应

**已知局限**：
- 无法检测"AI 使用了官方内容但未给链接"的情况
- 无法评估 AI 引用准确性（引用了但内容描述有误）
- 评分依赖 `official_urls` 人工标注的准确性

### 4.2 三状态评分模型

```
对于每个问题 q：

    if official_urls(q) == []:
        status = "no_official_content"   # 因为没有东西可以被引用
        severity = P1

    else:
        citation_rate = 被引用的平台数 / 总平台数
        cited_count = 被引用的平台数

        # 从 2026-05 起阈值改为 any_one（至少一个平台引用即满足）
        if cited_count >= 1:
            status = "satisfied"
            severity = OK
        else:
            status = "not_cited"         # 有内容但未被引用
            severity = P0
```

**阈值演变**：

| 版本 | 阈值规则 | 说明 |
|------|---------|------|
| v1.0（2026-04） | `citation_rate >= 0.75` | 75% 阈值，4 个平台中至少 3 个引用 |
| v1.1（2026-05） | `cited_count >= 1`（any_one） | 至少一个平台引用即判为 satisfied |

**any_one 阈值优势**：
- 更符合实际场景：只要有一个主流 AI 平台引用官方内容，即表明内容具备被引用的潜力
- 降低改进压力：从 75% 降至 any_one，新内容的达标门槛更合理
- 避免平台差异干扰：不同平台的索引覆盖率差异较大，any_one 规则减少了平台间差异对评分的影响

**75% 阈值仍保留用途**：
- 在 `summary/scoring-report.md` 中作为"良好覆盖率"的参考指标
- 用于区分 `satisfied` 问题中的高覆盖率（≥75%）与低覆盖率（<75%）

### 4.3 平台级别到问题级别的聚合

```
问题 q_001 | ChatGPT ❌ | DeepSeek ✅ | 豆包 ❌ | Qwen ❌
           → cited_count = 1
           → status = satisfied (>= 1 平台引用)
           → severity = OK

问题 q_002 | ChatGPT ✅ | DeepSeek ✅ | 豆包 ✅ | Qwen ✅
           → cited_count = 4
           → status = satisfied
           → severity = OK
```

### 4.4 从评分到建议的映射

评分完成后，系统从 72 条 GEO 建议目录中按状态匹配适用建议：

| status | 建议方向 | 示例建议 |
|--------|---------|---------|
| `not_cited` | 提升内容可发现性 | CTX-02（直接回答优先）、ORG-05（Schema 标记）、SITE-01（爬虫访问） |
| `no_official_content` | 创建新内容 | CTX-01（意图对齐）、EXC-06（填补空白）、ORG-02（摘要框） |
| `satisfied` | 持续优化保持优势 | EXC-01（原创数据）、EXC-08（深度优势）|

## 5. GEO 优化建议框架

本系统内置的 72 条 GEO 建议来自对 EEAT 框架在 AI 引用场景的延伸应用，分为 12 个维度。

### 5.1 框架来源

- **EEAT**（Google 的内容质量评估框架）：Experience（经验）、Expertise（专业性）、Authoritativeness（权威性）、Trustworthiness（可信度）
- **GEO 研究**：Princeton NLP Group 等机构发布的 GEO 学术研究（2023-2024）
- **实践总结**：基于对多个开源社区官网内容与 AI 回答差距的归纳分析

### 5.2 建议分类体系

| 类别代码 | 类别名称 | 条数 | 主要解决的问题 |
|---------|---------|-----|--------------|
| CTX | 上下文清晰度 | 9 | 内容是否直接回答用户问题 |
| ORG | 组织结构 | 9 | 内容是否便于 AI 解析和提取 |
| REF | 可引用性 | 8 | 内容是否有足够支撑其被引用的证据 |
| EXC | 独占性 | 10 | 内容是否有只有官方才能提供的独占价值 |
| DIS | 消歧义 | 4 | 专有术语是否会引发混淆 |
| NEG | 否定表达强化 | 5 | "不支持/不兼容"信息是否被 AI 正确传递 |
| VER | 版本 SEO | 3 | 版本化文档是否可能导致 AI 引用过期内容 |
| KWD | 关键词覆盖 | 3 | 覆盖用户的多种问法变体 |
| EXP | 经验信号 | 4 | 内容是否体现实际操作经验 |
| EPT | 专业性信号 | 6 | 内容技术深度是否形成引用壁垒 |
| AUT | 权威性信号 | 1 | 品牌是否有独立搜索量和实体识别 |
| TRU | 可信度信号 | 4 | 内容是否有透明的信息披露和更正机制 |
| SITE | 站点级建议 | 6 | 基础设施层面的爬虫可达性 |

### 5.3 优先级原则

建议的执行优先级参考：
1. **SITE-01/SITE-03**（爬虫访问权限、页面可渲染性）— 基础，不满足则后续所有优化失效
2. **CTX-02**（直接回答优先）— 最高 ROI 的单点优化
3. **ORG-05**（Schema 结构化标记）— 对 AI 解析帮助最大的技术改造
4. **EXC-01/EXC-03**（原创数据/第一方实验）— 独占性内容是引用率的终极保障

## 6. 开源社区的 GEO 特殊性

开源社区与商业产品在 GEO 场景下有若干显著差异：

### 6.1 内容分散性

开源社区的内容通常分散在：
- 官网文档（主站）
- GitHub/GitCode 仓库（README、Wiki、Issues、Discussions）
- 论坛（Discourse、Reddit）
- 第三方博客（CSDN、知乎、Medium）
- 视频平台（B站、YouTube）

**GEO 影响**：AI 平台综合以上来源时，如果第三方的描述与官方不一致，可能导致"有官方内容但 AI 引用了第三方错误版本"。

**对策**：提高官方内容的信息密度和权威性，同时确保 GitHub README 等第一梯队入口与官网一致。

### 6.2 版本碎片化

开源项目通常有多个历史版本长期并存，且各版本在文档站都有保留。

**GEO 影响**：AI 平台可能引用旧版本的文档，给用户带来安装失败、API 不存在等问题。

**对策**：旧版本文档页面设置 `canonical` 指向最新稳定版，EOL 版本添加 `noindex`，每个页面明确标注"适用版本"（VER 系列建议）。

### 6.3 竞品环境

以 MindSpore 为例，竞品（PyTorch、TensorFlow）在全球范围内的文档体量、社区活跃度和第三方内容数量远超 MindSpore。

**GEO 影响**：用户询问"如何迁移到 MindSpore"时，AI 可能因为找到的 PyTorch 内容更丰富而给出"直接用 PyTorch 更成熟"的建议，未能引用官方迁移指南。

**对策**：
- 针对竞品迁移场景创建专题迁移指南（EXC-06 填补空白）
- 在迁移指南中使用竞品术语进行对标（KWD-02 竞品对标术语）
- 提供可量化的迁移效益数据（EXC-01 原创数据）

### 6.4 贡献者分散的内容质量差异

开源社区文档通常由大量志愿者贡献，内容风格和质量不一致。

**GEO 影响**：部分页面可能存在术语使用不一致、结论写在末尾、无 FAQ 等问题，导致 AI 解析时提取到片面或错误的信息。

**对策**：建立 GEO 写作规范（基于 CTX/ORG 系列建议），纳入贡献者指南；对高频被问的核心文档进行专项 GEO 审计。
